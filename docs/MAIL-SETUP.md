# 校招通知自动接入：邮箱适配指南（方式 A 转发收口 / 方式 B IMAP 直读桥）

> 目标：把散落在邮箱里的校招通知（笔试 / 面试 / Offer / 感谢信）自动汇入工作台的
> **情报收件箱**，人工一键确认后写入投递跟踪表。
> 核心原则：**解析只产生"建议"，永不自动改状态**——识别错最多浪费一次点击，
> 不会静默把 Offer 改成感谢信（三级审核思路：自动解析 → 人工确认 → 落库）。

## 0. 两种方式怎么选

| | 方式 A · 转发收口 | 方式 B · IMAP 直读桥 |
|---|---|---|
| 原理 | 各邮箱设**自动转发规则**，关键词命中的邮件转发到收口邮箱 | 本地脚本用 **IMAP + 授权码**直接读邮箱 |
| 需要代码 | 否（设一次规则永久生效） | 是（`pages/mail_bridge.py`，纯标准库零依赖） |
| 需要密码/授权码 | 否 | 是（QQ 授权码 / Gmail 应用专用密码，**只存本地**） |
| 触发方式 | 邮件到达即转发（准实时） | 手动跑 / 定时任务轮询 |
| 适合 | 日常主力用法，最省心 | 想完全自主掌控、脱离收口邮箱时 |
| 风险 | 无凭据风险；换邮箱=加一条规则 | 授权码泄露面仅限本机；注意 `mail_config.json` 已进 `.gitignore` |

**两者可以并存**：方式 A 做日常兜底，方式 B 补抓历史/漏网邮件（`--since_days` 可调）。
无论哪种方式，解析层和数据层完全不变——适配只发生在"取信层"。

---

## 1. 前置：开通收口邮箱（两种方式都需要确认这一步）

方式 A 的转发目标、以及工作台 automation 的读取源，都是 WorkBuddy 的 **Agent Mail**：

1. 打开 WorkBuddy → 左下「更多」→「我的邮箱」→ 开通，得到一个专属邮箱地址。
2. 后续步骤里提到的 `<AGENT_MAIL>` 都填这个地址。

---

## 2. 方式 A：关键词自动转发（推荐先做）

原理：邮件到达你的邮箱 → 过滤规则按主题关键词命中 → 自动转发到 `<AGENT_MAIL>` →
收件箱管线解析。你不需要给任何第三方密码。

### 2.1 QQ 邮箱（网页版 mail.qq.com）

1. 登录网页版 QQ 邮箱 → 「设置」→「收发信设置」（旧版叫「收信规则」）。
2. 「创建收信规则」，条件勾选 **主题包含**，填：`面试,笔试,测评,offer,录用`（多个词分别建规则，或用"满足任一条件"）。
3. 执行动作勾选 **自动转发至** → 填 `<AGENT_MAIL>`。
4. 首次转发到新地址时，目标邮箱会收到一封**验证邮件**，去 WorkBuddy「我的邮箱」里点确认，规则才生效。
5. 保存后自己发一封测试邮件（主题含"面试"）验证链路。

### 2.2 Gmail

1. myaccount.google.com 登录 → Gmail → 齿轮「查看所有设置」→「转发和 POP/IMAP」。
2. 「添加转发地址」→ 填 `<AGENT_MAIL>` → 去目标邮箱点验证邮件。
3. 转到「过滤器和屏蔽的地址」→「创建新的过滤器」→ **主题包含** 填
   `面试 OR 笔试 OR 测评 OR offer OR 录用`（Gmail 过滤器语法支持 OR，需大写）。
4. 勾选「转发给：<AGENT_MAIL>」→ 创建过滤器。建议再建一条同样条件的过滤器勾
   「标记为已读」避免原邮箱堆积。

### 2.3 短信（安卓，可选）

装「短信转发器」类 APP（如 SmsForwarder，开源），按关键词（面试/笔试/校招）
触发 → 转发到 `<AGENT_MAIL>`。邮件和短信天然汇成同一条管线，解析器不用改。

## 3. 方式 B：IMAP 直读桥 `pages/mail_bridge.py`

### 3.1 拿到凭据（授权码 ≠ 登录密码）

**QQ 邮箱：**
1. 网页版 QQ 邮箱 → 「设置」→「账户」→ 往下找「POP3/IMAP/SMTP 服务」。
2. 开启「IMAP/SMTP 服务」→ 按提示发短信验证。
3. 同一页面「生成授权码」→ 得到 **16 位授权码**（只显示一次，记下来）。
4. 服务器参数：`imap.qq.com:993` SSL（脚本已内置，配置里选 `qq` 即可）。

**Gmail：**
1. myaccount.google.com → 「安全性」→ 确认已开启**两步验证**（没有就先开）。
2. 安全性页搜「应用专用密码 / App passwords」→ 生成一个 → 得到 **16 位应用密码**。
3. Gmail 设置 →「转发和 POP/IMAP」→ 启用 IMAP。
4. 服务器参数：`imap.gmail.com:993` SSL（脚本已内置，配置里选 `gmail`）。

### 3.2 配置

```bash
copy pages\mail_config.example.json pages\mail_config.json
# 编辑 mail_config.json：填 user + auth_code；不用的邮箱删掉对应条目
```

字段说明：

| 字段 | 说明 |
|---|---|
| `accounts[].provider` | `qq` / `gmail` / `163` / `outlook`（预设了 IMAP 服务器） |
| `accounts[].user` | 完整邮箱地址 |
| `accounts[].auth_code` | 授权码 / 应用专用密码（**本地保存，已 gitignore，绝不提交**） |
| `keywords` | 命中词（脚本内置了一套分类规则，这里留给未来扩展） |
| `exclude` | 排除词，防止「面经分享」被误判成面试通知 |
| `since_days` | 往回抓几天（首次建议 7，日常 1-3） |
| `max_per_account` | 每账号单次最多处理多少封，防止首次全量拖慢 |

### 3.3 运行（三种模式）

```bash
# ① 自测解析器（不需要邮箱，内置 5 封样例）
python pages/mail_bridge.py --self-test

# ② 空跑：连接邮箱解析并打印，不写任何地方（建议第一次就这么跑）
python pages/mail_bridge.py --dry-run

# ③ 写本地队列 pages/mail_outbox_queue.json（攒着，之后手动推/贴进工作台）
python pages/mail_bridge.py --out local

# ④ 直写资料库「求职情报收件箱」表（token 30 分钟有效，过期重取）
printf '%s\n' '<token>' | python pages/mail_bridge.py --out api --token-stdin
```

token获取：在 WorkBuddy 对话里让 AI 执行「连接资料库技能（connect_open_platform）」即可取得，
或从资料库技能页面复制。API 写入失败时脚本会自动把记录落到本地队列兜底，不丢数据。

### 3.4 定时化（可选）

Windows 任务计划程序 → 创建基本任务 → 每天 09:00 → 启动程序
`python`，参数 `pages/mail_bridge.py --out local`，起始于项目目录。
（也可以在 WorkBuddy 里建 automation 定时提醒自己跑一次 `--out api`。）

### 3.5 去重

`pages/mail_seen.json` 记录已处理的 `账号|Message-ID`，重复跑不会产生重复记录。
删除该文件即可强制重抓（配合 `since_days` 调大）。

## 4. 数据流向与人工确认

```
邮箱 → [方式A 转发 | 方式B IMAP桥] → 解析（类型分类·公司归一化·置信度分级）
     → 情报收件箱表（状态=待确认）→ 工作台总览台「情报收件箱」区
     → 点「确认」展开写入条（阶段已按类型预填）→ 写入投递跟踪表
     → 点「忽略」归档
```

置信度分级逻辑：关键词命中 ≥2 处 = 高；命中 1 处 = 中；公司域名陌生 = 封顶中；
命中排除词（面经/攻略/回忆版）= 直接过滤或标低。

---

## 5. 隐私与安全

- **授权码只存本机** `pages/mail_config.json`（已在 `.gitignore`，永远不会被提交）；
  撤销方式：QQ 邮箱账户页「删除授权码」/ Google 账号移除应用密码。
- 脚本对邮箱 **只读**（`readonly` 打开 INBOX），不删不改不标已读。
- 抓取范围仅限 `since_days` 天内的邮件，且只有命中校招关键词的才进入解析。
- 原文摘要截断 500 字，收件箱表里不存全文。
- 资料库 API 用短时 token（30 分钟），凭据零长期驻留。

## 6. 故障排查

| 现象 | 原因 / 处理 |
|---|---|
| QQ 登录失败 `(b'LOGIN Login fail.')` | 授权码错了/过期 → 重新生成；确认 IMAP 服务已开启 |
| Gmail 报 `AUTHENTICATE failed` | 应用密码错；确认两步验证开启、Gmail 设置里 IMAP 已启用 |
| 中文月份/日期搜索报错 | 脚本已内置英文月份拼接，若自行改代码注意 IMAP `SINCE` 需 `14-Sep-2026` 格式 |
| 命中 0 条但邮箱里明明有 | `since_days` 太短；或邮件是 HTML 且关键词只在图片里（脚本无法 OCR，属于方式A也解决不了的场景） |
| 写 API 401 | token 过期（30 分钟），重新获取再跑 |
| 公司名识别为「（未识别）」 | 正常兜底，确认时在工作台手动改一下即可 |

## 7. 面试怎么讲这个模块（项目筹码）

**30 秒版本**：
> 我给自己的求职工作台做了一个通知自动接入管线：邮件里的笔试/面试/Offer 通知，
> 通过两条可插拔的取信通道（关键词自动转发 / IMAP 授权码直读桥）汇入统一消息格式，
> 解析器做类型分类、公司归一化和置信度分级，写入"收件箱"表；关键是解析结果**只产生建议**，
> 必须人工确认才真正改投递状态——用一次点击的成本换掉了静默改错的风险。

**可深挖的点（面试官追问时的弹药）**：
1. **适配层设计**：取信/解析/存储三层解耦，换邮箱只动取信层（转发 or IMAP 可插拔），解析器零改动——对应"开闭原则"。
2. **置信度分级**：关键词多重命中+已知公司域名=高；陌生域名封顶中；这是"机器给建议、人对不确定负责"的量化落地。
3. **误判防御**：排除词（面经/回忆版/攻略）先行，解决招聘邮件最常见的分享类邮件误判。
4. **反爬规避**：邮件和短信是官方主动推给你的通道，没有反爬问题——对比直接爬招聘官网的方案为什么不可行。
5. **工程兜底**：API 失败自动落本地队列不丢数据；Message-ID 去重；单封坏邮件不影响整批。
6. **安全边界**：IMAP 只读打开、授权码本地存储且 gitignore、原文只存 500 字摘要、API 用 30 分钟短时 token。
