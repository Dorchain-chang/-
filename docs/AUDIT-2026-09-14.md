### 1.3 本轮安全加固（改动前后对照）

| 项目 | 改动前 | 改动后 | 为什么 |
| --- | --- | --- | --- |
| 外链出口 | `window.open(link,'_blank')`，协议不校验 | 统一走 `openLink()`：`trimStr` → `isHttpUrl` 白名单 → 非法协议**直接拦截** → `window.open(url,'_blank','noopener,noreferrer')` | ① 挡住 `javascript:` / `data:` 这类可执行协议；② `noopener` 防止被打开页面通过 `window.opener` 反向操纵本页（本页内存里有全部投递数据）；③ `noreferrer` 让第三方**收不到 Referer**，不会泄漏你的文档地址 |

| 顶部同步状态 | 只在「已同步 / 离线模式」二态，失败时静默 | 四态 `已同步 / 同步异常 / 同步失败 / 离线模式`，异常时有橙色指示 | 让「拉数失败」可见，而不是假装成功 |

### 1.4 残余风险（如实说明，需你判断）

1. **页面本身没有 CSP**。理论上可加 `Content-Security-Policy` 收紧，但资料库 SDK 与宿主页面的通信方式（postMessage 还是同源请求）未公开文档化，贸然加 `connect-src 'none'` 有把 SDK 打死、整页不可用的风险。当前用「零外部资源依赖」这个更强的静态事实替代。**建议：保持现状；若日后要加，先在测试节点验证。**
2. **第三方链接仍会收到公司名**。点「牛客 · 面经」时，URL 里含 `?query=公司名`，也就是你正在关注哪家公司会暴露给牛客。这是「点情报」这个功能的必要代价，无法避免；已用 `noreferrer` 去掉了更敏感的文档地址。
3. **`data-sp-bindable` / `data-sp-database-id` 属性**是资料库 SDK 的约定（告诉宿主页面这块 DOM 绑定了哪张表），属于平台要求，非泄漏。
4. **表单草稿存在浏览器 localStorage 里**，是明文。同一台电脑的其他使用者理论上可读。已排除敏感字段；如果你共用设备，可在表单里手动清空或告诉我加一键清除入口。

## 4. 稳定性

### 4.1 P0：修复「整页白屏」的转义陷阱（本轮最有价值的发现）

**现象**：给 `openLink` 加协议白名单时写了 `replace(/[\u0000-\u001f]/g,'')`，构建产物里出现 2 个裸控制字符（NUL 0x00 / 0x1F）。HTML 解析阶段会把裸控制字符替换成 U+FFFD，正则于是变成 `[U+FFFD-0x1F]` → **Range out of order in character class** → 整个 `<script>` 语法错误 → **页面全白，什么功能都没有**。

**为什么之前的检查漏掉**：`node --check` 和 `new Function()` 都报 OK —— 文件里是合法的 NUL 字节，不是非法转义；只有真正用浏览器加载才会炸。**这次是靠新增的浏览器冒烟测试抓出来的。**

**根因**：`build_pages.py` / `build_single.py` 里的大段 JS 是**普通（非 raw）三引号串**，Python 会先把 `\u0000`、`\x1f`、`\b`、`\v` 当成自己的转义解析掉。

**双保险修复**：
1. 代码侧：`openLink` 改成不依赖反斜杠转义的写法（`trimStr` 用 `charCodeAt` 判断、`isHttpUrl` 用 `indexOf`、域名判断用字符扫描）。
2. 工程侧：新增 `pages/check_escapes.py` 构建守卫 —— ① 扫源码里所有「会被 Python 解释的转义」（白名单只有刻意的 `\n` `\t`）；② 扫产物里是否有裸控制字符（`< 0x20` 非 `\n\r\t`、或 `0x7F`）。已自测：故意注入旧 bug 能被拦下。并且加进了 CI `lint.yml`。

### 4.2 其他稳定性加固

| 项目 | 改动 |
| --- | --- |
| **拉数失败自动重试** | `loadData` 失败自动重试 1 次（间隔 1.5 s），仍失败才置「同步异常」并把错误显示在顶部状态点 |
| **失败不阻断渲染** | `reloadAll()` 无论成功失败都会跑 `refreshAll()`，失败时展示上一次的数据，而不是空白 |
