# AI 能力说明（BYOK · 按需触发）

> 一句话：**看和算的部分零成本，只有「问模型」的那一下才花钱，而且花的是你自己的 Key。**
>
> 本文对应版本 v27。涉及代码：`pages/build_pages.py` 中的 `AI_CORE_JS` / `MATCH_JS` / `AI_PLUS_JS` 三个共享脚本常量。

---

## 一、两条设计原则

| 原则 | 含义 | 为什么这么做 |
|---|---|---|
| **BYOK（自带 Key）** | 页面「AI 设置」里填你自己的 API Key，存在本机浏览器 `localStorage`，**不上传任何服务器、不进资料库表** | 开发者零 token 成本；用户数据不出本机；谁的账谁付，消耗透明 |
| **按需触发，无常驻后台** | 没有后台进程、没有定时任务。只有你点按钮那一刻才调用模型；排序、筛选、紧迫度判断全部用本地规则 | 常驻后台（盯邮箱/定时全量打分）的收益与成本不成正比：关掉页面就不该继续烧钱 |

配套的兜底：**任何 AI 调用失败都会回落**——没配 Key 时返回带「演示数据」标注的 Mock 结果，页面永不白屏；网络失败时提示重试，原有规则功能不受影响。

## 二、能力总览

| 能力 | 入口 | 触发方式 | 单次 token 估算 | 结果存哪 |
|---|---|---|---|---|
| 简历档案解析 | 总览台 → 个人中心 → **简历档案** | 支持 txt / md / **docx（Word）** 直接上传或粘贴文本，点「AI 解析」 | 2–4k | 本机 `wb_resumes` |
| 投递画像 | 个人中心 → **投递画像** | 点「生成投递画像」 | 2–3k | 本机 `wb_profile` |
| 单岗位匹配打分 | 岗位卡片 → **贴 JD 打分** | 点按钮 | 1–2k | 本机 `wb_jd` / `wb_match` |
| 批量匹配打分 | 岗位页筛选区 → **批量打分** | 点按钮（**一次最多 8 条**，可中断） | 约 2k × 条数 | 同上 |
| 今日 AI 推荐 | 今日提醒顶部 → **AI 今日推荐** | 自动本地排序（**0 成本**）；点「AI 点评」才调模型 | ≈1k（当天缓存） | 本机 `wb_reco` |
| 面试复盘 | 投递跟踪卡片 → **AI 复盘** | 点「生成复盘」 | 2–3k | 本机 `wb_review` + 云端「复盘笔记」 |
| 邮件 AI 解析 | 收件箱卡片 → **AI 解析** | 点按钮 | ≈1k | 本机 `wb_ibai` |
| 抓 JD 书签 | 贴 JD 弹窗 → **抓 JD 书签** | 在招聘页点书签 | 0（不进模型） | 系统剪贴板 |

**成本控制几个具体设计**

- 批量打分硬上限 8 条（`MT_BATCH_MAX`），点击时先弹确认并告知预估消耗；跑的过程中按钮变「停止」，随时可中断，剩下的下次继续。
- 今日推荐默认是**本地规则排序**（匹配分 50% + 截止紧迫度 30% + 意向吻合 20%），一次模型调用都不发生；只有你点「AI 点评」才用一次调用给全部推荐项写理由，且结果按天缓存在本机，同一天再点不重复消耗。
- 打分/解析这类要求稳定复现的任务温度锁定 `0.2`，简历定制/复盘这类需要表达力的用 `0.4–0.5`。

## 三、配置（一次性）

1. 打开总览台 → **个人中心** → **AI 设置**
2. 选服务商（DeepSeek / Kimi / 通义千问 / 智谱 GLM / OpenAI 兼容自定义），Base URL 与默认模型名会自动带出，可改（支持中转站与私有部署）
3. 填 **API Key**
4. 点「测试连接」→ 状态变成「已连接」

**建议**：去服务商后台**专门为这个工具建一个 Key 并设置消费上限**（比如 10 元）。这样即使发生最坏情况（Key 泄露），损失也可封顶，且随时可单独吊销。

「记住 Key」开关关掉后 Key 只存 `sessionStorage`，关闭浏览器即失效——公用电脑上建议关掉。

## 四、抓 JD 书签（零安装）

牛客列表接口只返回公司/批次/方向/城市/截止时间/投递链接，**没有 JD 正文**（详情页是前端渲染 + 反爬）。所以 JD 走「人工贴一次」：在官网复制太麻烦，用这个书签一步搞定。

**书签代码**（整段复制）：

```
javascript:(function(){var s=document.body.innerText||"";var k=s.search(/职位描述|岗位描述|工作职责|任职要求|岗位职责|职责描述|Responsibilities|Job Description/i);if(k>0)s=s.slice(k);s=s.slice(0,6000);if(navigator.clipboard&&navigator.clipboard.writeText){navigator.clipboard.writeText(s).then(function(){alert("已复制岗位 JD（"+s.length+" 字）。回到秋招求职台的岗位卡片，点「贴 JD 打分」粘贴即可")},function(){prompt("自动复制被浏览器拦截，请手动复制：",s)})}else{prompt("请手动复制以下 JD 文本：",s)}})();
```

**添加方式（一次性）**

1. 浏览器书签栏右键 → 「添加网页 / 新建书签」
2. 名称填 `抓JD`，网址栏把上面整段粘贴进去，保存
3. 以后在任意招聘页（牛客 / 公司官网 / BOSS）点这个书签 → JD 自动进剪贴板
4. 回到求职台，岗位卡片点「贴 JD 打分」→ 粘贴 → 保存并打分

页面里的「贴 JD 打分」弹窗也提供了 **抓 JD 书签** 按钮，点一下会自动复制上面这段代码并提示添加步骤。

**为什么不做浏览器扩展**：扩展需要用户开开发者模式加载，门槛高；书签是零安装、零权限、不可能有反爬风险的方案。将来若要做「一键同步官网投递状态」，会另起一个扩展方案（用户在自己浏览器里已登录，页面内抓取，风险仍在用户侧）。

## 五、邮件 AI 解析（两个入口）

### 入口 1：页面内（收件箱卡片 → AI 解析）

把邮件的**原始摘要**交给模型，输出结构化结果：

- **环节**：笔试 / 一面 / 二面 / HR面 / Offer / 感谢信 / 其他
- **时间**：`YYYY-MM-DD HH:MM`
- **形式**：线上 / 线下 / 待定
- **地点**：会议链接或地址
- **准备**：2–4 条需要准备或注意的事项
- **待办**：1–3 条需要立刻做的事

解析结果展示在卡片上，并**自动成为「确认 → 写入投递跟踪」时默认选中的阶段**（照样要点确认才写库，AI 不改状态）。

### 入口 2：本地 IMAP 桥（`pages/mail_bridge.py --llm`）

`mail_bridge.py` 默认是**纯关键词规则**解析，零依赖零成本。加上 `--llm` 后会对通过关键词过滤的邮件再做一次模型结构化：

```bash
# 方式 A：写在 mail_config.json 的 llm 段里
python pages/mail_bridge.py --llm --dry-run

# 方式 B：环境变量（优先于配置文件）
MAIL_LLM_BASE=https://api.deepseek.com/v1 \
MAIL_LLM_KEY=sk-xxx \
MAIL_LLM_MODEL=deepseek-chat \
python pages/mail_bridge.py --llm --out api --token-stdin
```

模型结果会**纠正**规则判定的类型（置信度升为「高」）、把识别出的时间写进「事项时间」，并把「时间/形式/地点/待办」以 `[AI]` 前缀追加到摘要末尾。**调用失败一律静默回落规则解析**，不影响写库。

> 邮箱接入的完整教程（转发收口 / IMAP 直读）见 [`MAIL-SETUP.md`](MAIL-SETUP.md)。

## 六、隐私与安全模型

| 角色 | 数据在哪 | 谁能看到 |
|---|---|---|
| 你（资料库账号打开） | 云端 4 张表 + 本机缓存 | 只有你 |
| 任何其他访客 | 只存在访客自己的浏览器（连接失败自动进离线模式） | 只有访客自己 |

**不存在「服务器上堆着所有用户的私密数据」**——这个项目没有自己的后端，页面是静态单文件，数据要么在你的资料库空间，要么在用户本机。

会发给模型的内容：简历文本、岗位 JD、面试记录、邮件摘要。仅你配置的服务商可见。

**已知风险（不隐瞒）**：能物理接触你电脑的人可以用开发者工具看到 Key（与浏览器「记住密码」同级）；高权限浏览器扩展理论上可读取；若页面被注入恶意脚本可窃取 Key（本项目零第三方 JS 依赖，注入面极小）。**最有效的对策是给 Key 设消费上限。**

## 七、常见问题

**Q：点了按钮没反应 / 提示 Mock？**
没配 Key 时所有 AI 功能都会返回「演示数据」，用于先看交互效果。到「AI 设置」填 Key 并测试连接即可。

**Q：报 CORS / 跨域错误？**
部分服务商不允许浏览器直连。可改用允许浏览器调用的服务商，或把 Base URL 换成你的中转站地址。

**Q：报 429 / 请求过于频繁？**
批量打分是逐条串行的，已尽量温和；若仍触发限流，把一次批量条数改小（`AI_PLUS_JS` 里的 `MT_BATCH_MAX`）或等几分钟。

**Q：打分结果会同步到云端吗？**
不会。匹配分、JD、复盘、推荐、解析结果全部只存本机。唯一写云的是**面试复盘写入投递跟踪的「复盘笔记」字段**（这是你可见、可删的正常字段），以及收件箱确认后写入投递跟踪。

**Q：换台电脑要重新配吗？**
Key 和简历、打分结果都在本机，换设备需要重配。这是「数据不出本机」的代价，当前阶段有意如此（个人使用、互不联通）。
